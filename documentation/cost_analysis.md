# QISO Cost Analysis

**Document:** `cost_analysis.md`  
**System:** QISO - RAG for ISO Quality Management and Internal Auditing  
**Currency:** USD  
**Purpose:** Estimate monthly operating cost for 1,000, 10,000, and 100,000 active users.

> **Important:** This is a system-specific engineering estimate, not an invoice. It uses measurements from the current QISO project and current/commonly published Cohere rates. Actual production billing should be verified against Cohere billed units and any negotiated production pricing.

## 1. Scope

The estimate covers the variable AI/API cost generated by a normal QISO question:

1. Arabic-to-English translation for BM25 when the question is Arabic.
2. Query embedding with `embed-multilingual-v3.0`.
3. Hybrid retrieval with local ChromaDB + BM25 + RRF.
4. Reranking with `rerank-multilingual-v3.0`.
5. Grounded answer generation with `command-a-03-2025`.

Local ChromaDB/BM25 retrieval has no direct per-query API fee. Hosting, bandwidth, monitoring, backups, paid Streamlit/server infrastructure, and support are **not** included because no production hosting tier has been selected.

## 2. Measurements from the current QISO system

The following values were measured from the current project and the final RAGAS dataset:

| Item | Measured value |
|---|---:|
| RAGAS questions | 30 |
| Stored Chroma chunks | 1,553 |
| Average question length | 76.1 characters |
| Average answer length | 720.2 characters |
| Average stored chunk length | 599.8 characters |
| Contexts sent to generation | 5 |
| Estimated context text per question | 2,999.2 characters |
| System prompt length | 740 characters |
| Retrieval candidates before reranking | 20 |
| Final contexts after reranking | 5 |

The 2,999.2-character context value is calculated as `5 × 599.8`. It is therefore an estimate based on the corpus average, not a direct measurement of the exact five chunks retrieved for every question.

## 3. Cost assumptions

### 3.1 Monthly usage assumption

To convert users into requests, the base scenario assumes:

**10 questions per active user per month.**

Therefore:

- 1,000 users -> 10,000 questions/month
- 10,000 users -> 100,000 questions/month
- 100,000 users -> 1,000,000 questions/month

A sensitivity table for 5 and 20 questions per user is included later.

### 3.2 Estimated tokens per question

QISO sends the system prompt, the user question, five source chunks, source/page labels, and answer instructions to the generation model. Based on the measured text lengths above, the base estimate is:

| Component | Estimated tokens/question |
|---|---:|
| Command A input | 1,150 |
| Command A output | 290 |
| Query embedding | 30 |

The token values are approximations because the current logs do not store Cohere `billed_units`. The final production bill should use Cohere's billed token counts rather than character-to-token estimates.

### 3.3 Pricing assumptions

| Service | Rate used in this analysis |
|---|---:|
| Command A input | $2.50 / 1M tokens |
| Command A output | $10.00 / 1M tokens |
| Embed Multilingual v3 | $0.10 / 1M input tokens* |
| Rerank Multilingual v3 | $2.00 / 1,000 searches* |
| Command A Translate | $0 in base estimate; production pricing must be confirmed with Cohere |

`Command A` pricing is published by Cohere. Cohere also defines Rerank billing by search units, where one query with up to 100 documents is one search unless long-document chunking increases the document count. QISO reranks up to 20 candidates, and the average stored chunk is about 600 characters, so the analysis assumes one Rerank search unit per user question.

\* Cohere's current public pricing page does not expose a specific list price for the older v3 Embed/Rerank models used by QISO. The rates above are retained as planning assumptions consistent with widely published v3 pricing and should be reconfirmed before production procurement.

`Command A Translate` is currently described by Cohere as free until rate limits are reached, while production use requires contacting Cohere. For that reason its dollar cost is not invented here and is excluded from the numerical total.

## 4. Estimated cost per question

### Command A generation

Input:

`1,150 × $2.50 / 1,000,000 = $0.002875`

Output:

`290 × $10.00 / 1,000,000 = $0.002900`

Generation total:

`$0.002875 + $0.002900 = $0.005775`

### Reranking

One search unit per question:

`$2.00 / 1,000 = $0.002000`

### Query embedding

`30 × $0.10 / 1,000,000 = $0.000003`

### Base variable AI cost

`$0.005775 + $0.002000 + $0.000003 = $0.007778`

**Estimated variable AI cost per answered question: approximately $0.0078.**

At 10 questions per user per month, the estimated AI cost is approximately **$0.0778 per active user per month**.

## 5. Monthly scenarios

| Active users/month | Questions/user | Questions/month | Estimated AI cost | With 15% operating buffer |
|---:|---:|---:|---:|---:|
| 1,000 | 10 | 10,000 | **$77.78** | **$89.45** |
| 10,000 | 10 | 100,000 | **$777.80** | **$894.47** |
| 100,000 | 10 | 1,000,000 | **$7,778.00** | **$8,944.70** |

The 15% buffer is included to absorb normal variation in response length, tokenization, retries, and usage distribution. It does **not** cover a separately negotiated Command A Translate production fee or infrastructure costs.

## 6. Cost composition

Under the base assumptions, the approximate per-question cost is distributed as follows:

- **Command A generation:** ~$0.00578/question (about 74%)
- **Reranking:** ~$0.00200/question (about 26%)
- **Query embedding:** negligible relative to the other components
- **ChromaDB + BM25 + RRF:** no direct API fee; consumes local/server compute
- **Translation:** excluded from the numeric total because production commercial pricing is not publicly fixed for this model

The largest cost driver is therefore answer generation, followed by reranking.

## 7. Usage sensitivity

Because actual user behavior may differ from the 10-question assumption, the following table shows the approximate model/API cost before the 15% buffer:

| Active users | 5 questions/user | 10 questions/user | 20 questions/user |
|---:|---:|---:|---:|
| 1,000 | $38.89 | $77.78 | $155.56 |
| 10,000 | $388.90 | $777.80 | $1,555.60 |
| 100,000 | $3,889.00 | $7,778.00 | $15,556.00 |

This demonstrates that QISO's variable AI cost scales almost linearly with the number of questions rather than simply with registered users.

## 8. Costs not included

The following items should be budgeted separately for a real production deployment:

- Production web hosting / application servers
- Memory and CPU required for ChromaDB and BM25
- Persistent storage and backups
- Monitoring, logging, and observability
- Network egress where applicable
- Authentication/user-management services if expanded beyond the current simple login
- Technical support and maintenance
- Re-ingestion when the document corpus changes
- Any negotiated production charge for `command-a-translate-08-2025`

The current corpus contains only 1,553 chunks, so vector storage itself is small. At very high traffic, compute concurrency and API rate limits become a more important scaling concern than vector storage size.

## 9. Interpretation and recommendation

For the current QISO architecture, a reasonable planning figure is **about $0.008 per answered question**, excluding hosting and any negotiated translation charge. With the assumed 10 questions per active user per month, the variable AI budget is approximately **$78 / $778 / $7,778 per month** for 1,000 / 10,000 / 100,000 users respectively, before the recommended 15% buffer.

The 100,000-user scenario should not be treated as deployable using a Trial API key. QISO would require production API access, higher rate limits, suitable hosting, concurrency testing, and confirmation of commercial terms for the translation model.
